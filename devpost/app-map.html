Notice Paper — App Map

Interactive architectural guide and code route for understanding how plain-language interpretation and verbatim verification work.

Snapshot Commit: 816c0d6 • Node.js 18+ • Express & Google Gemini API

1. The Big Picture

Notice Paper solves official mail paralysis by turning intimidating letters and bills into 5 calm, structured answers: Deadline & Amount, Plain Summary, Consequences, Up to 3 Next Steps, and Also Worth Knowing.

The app is built with 3 core moving parts:

  • Frontend Client (public/index.html, public/app.js, public/style.css): Collects letter text, validates boundaries (<15 words, >10,000 characters, empty), renders loading states, and draws verified badges.
  • Server & API Controller (server.js): Enforces a 50kb payload limit, wraps letters in passive <letter_document> tags for prompt injection defense, and queries Gemini with native structured outputs.
  • Deterministic Verbatim Verifier (server.js): Programmatically checks whether AI-extracted deadlines and amounts literally appear in the source text, normalizing whitespace variations.

2. Guided Code Route: Following One Real Action

To understand how Notice Paper works under the hood, let's trace what happens from the exact moment you click "Explain this letter" to the moment the verified result cards appear on your screen.

Stop 1: The Input & Trigger

Browser Entry Point & Validation

File: public/app.js (Search anchor: btnExplain.addEventListener / validateInput)

When the user clicks the explain button, validateInput() checks the letter text immediately:

  • If text is empty, under 15 words, or over 10,000 characters, it stops right away, clears any stale previous results/notices, and shows a friendly inline alert.
  • If valid, it sets the loading skeleton state and sends an asynchronous POST /api/explain request carrying { text, language }.
Stop 2: The AI Processing Kernel

Server Route, Prompt Defense & Structured Output

File: server.js (Search anchor: app.post('/api/explain' / responseSchema)

The Express backend receives the letter. It protects the application through three layers:

  • Passive Isolation: The user's letter is enclosed inside <letter_document>...</letter_document> tags so that instructions like "ignore previous instructions" cannot hijack the model.
  • Zero Logging: The server never logs the letter text to the console, protecting user privacy.
  • JSON Schema Enforcement: Instead of asking Gemini to write arbitrary text, it passes responseSchema to guarantee fields like amount_due, deadline, summary, and next_steps arrive cleanly.
Stop 3: Output Grounding

Verbatim Substring Verification & Badge Rendering

Files: server.js (Search anchor: verifyVerbatimSubstring) & public/app.js (Search anchor: renderResults)

Before sending the answer back to the user, the server runs a deterministic JavaScript substring search on the raw letter text:

function verifyVerbatimSubstring(candidate, fullText) {
  if (!candidate || !fullText) return false;
  return normalizeWhitespace(fullText).includes(normalizeWhitespace(candidate));
}

If the extracted deadline and amount exist literally in the letter, it sets amount_verified: true. The frontend then draws the green "Found in the letter" badge. If the model altered or fabricated a number, a terracotta warning badge is displayed instead.

3. "To Change This, Start Here"

Quick reference pointers for modifying or extending Notice Paper in the future:

Card text, translations, or error wording:
Edit the I18N dictionary in public/app.js (lines 13–146). Both English (en) and Bahasa Indonesia (id) strings are organized side-by-side.
Gemini Model or Server Port:
Edit .env. You can change GEMINI_MODEL=gemini-3.5-flash-lite to any supported Google Gemini model or alter PORT=3000 without modifying code.
AI Instructions & Interpretation Rules:
Edit systemInstruction in server.js (lines 75–125). Here you can calibrate rules (e.g. earliest deadline pairing, tone, or uncertainty detection).
Visual Styling, Colors, and Typography:
Edit public/style.css. Notice Paper uses a 60/30/10 CSS custom property palette (--bg-canvas: #F2EFE8, --bg-card: #FAF8F5, --accent-terracotta: #C05621).
View Safe Incidental Edit Example (Custom Reassurance Message)

Want to personalize the app? Open public/app.js, find errorReassurance in I18N.en, and modify the reassurance string from:

errorReassurance: "Your letter is still safe in the box and hasn't been lost."

to whatever comforting message you prefer. When an error occurs, the user will see your updated text immediately upon browser refresh.

4. A Practice to Reuse: Deterministic Output Grounding

Never Ask an LLM to Verify Its Own Factual Extraction

Large language models excel at summarizing, explaining, and simplifying complex text. However, they can produce subtle hallucinations or alter numbers and dates without warning.

The reusable architectural pattern:

  1. Let the AI extract the candidate fact (e.g. $60.00 or November 3, 2026).
  2. Have your server run a deterministic, traditional code check (like fullText.includes(candidate) with whitespace normalization) against the ground-truth user input.
  3. Render explicit confidence badges to the user based on that deterministic check.

This guarantees you never present an ungrounded number as verified fact, while keeping your architecture fast, cheap, and completely predictable.

To restart Notice Paper at any time on your machine:

npm install

# 2. Start the Express server
npm start

http://localhost:3000

npm test
